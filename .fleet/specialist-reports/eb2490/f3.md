## Findings — things that look wrong in files I do not own

Reported, not edited.

### 1. `isoDay` renders a zone-less timestamp a day early east of UTC — MEASURED

`src/lib/display-format.ts`'s `isoDay` reduces through
`new Date(Date.parse(v)).toISOString().slice(0,10)`. `Date.parse` reads a timestamp stating no zone
(`2026-09-01T00:00:00`, no `Z`, no offset) as **local** time, so `toISOString()` shifts it. Measured
in this worktree:

```
$ TZ=Pacific/Kiritimati node -e '...'
TZ           : Pacific/Kiritimati
isoDay-style : 2026-08-31
formatDate   : 2026-09-01
```

`formatDate` in `registry-display.ts` handles this deliberately and carries the comment explaining
why. `isoDay` does not, and `isoDay` is what `src/app/waits/_components/wait-list.tsx` renders wait
dates with. **All three f3 views use `formatDate` and are not affected**; the wait *listing* is.
Whether any of those columns actually holds a zone-less value is a database question I have no
credential to answer, so this is a latent defect and not an observed one. `display-format.ts` is
outside this unit's ownership; not touched.

### 2. Two money formatters that disagree on shape

`formatAmount` (registry-display.ts) renders `$111.00`; `money` (money-display.ts) renders
`111.00 USD`. `/registry/[slug]` uses the first, `/committed` the second, and `/milestones/[id]` now
uses the first because the brief named it. The same milestone therefore reads two ways on two
screens. `money-display.ts` is in the no-edit list; queued as question 2.

### 3. `Prose` has no shared renderer, so up to three Wave C units will each write one

`renderProse` handles four states and belongs in `src/components/` beside `EntityDetail`. It is in
`src/app/milestones/_components/` instead because Wave C's five units own disjoint **route**
directories and none of them owns a shared component home — and creating one in `src/components/`
would collide with f1 or f2 doing the same at merge. f1 and f2 render five `Prose` fields between
them. **Recommend a follow-up that hoists one implementation and deletes the copies**; three
implementations of "what does `unreadable` look like" is exactly the drift the rulings exist to
prevent, applied to a treatment rather than a derivation.

### 4. `EntityDetail` cannot omit its identifier

`identifier` renders `Absent` — *"this X carries no reference of its own"* — for both `null` and
`undefined`. On all three of f3's kinds the human reference **is** the title, so the view either
duplicates the string or makes a false claim. Duplicated; queued as question 1. Not an edit to
`entity-detail.tsx`.

## Best-guess decisions

1. **`identifier` duplicates the title on all three views.** The alternative states a falsehood.
   Question 1.
2. **`formatAmount` over `money`.** The brief names it. Question 2.
3. **Day resolution on every date.** Question 3.
4. **`loadForOperator` wraps each read rather than a bare `try`.** The registry precedent hand-rolls
   a `try` and maps to a `GateRefusal`; `loadForOperator` is the same discipline, already exists, is
   what the other eleven screens use, and gives the four refusal reasons the `load-notice` contract
   the e2e gate queries. `notFound()` is called strictly outside it — inside, its `catch` would
   swallow the throw and report a database failure for a row that simply does not exist.
5. **`external_wait`'s `reason` renders as a plain string, not through `renderProse`.** §7a leaves it
   clear and the loader's type has no `Prose` on it. Looking for four states in a `string | null`
   would be a promise the type does not make.
6. **The back-links: wait → `/waits`, release → `/untested`, milestone → its engagement.** `release`
   and `contract_milestone` have no listing screen of their own. FR-84's filter restoration is
   browser-`goBack()` and is unaffected by these.
7. **No overdue chip on the wait view, no shipped chip on the release view, no milestone-state chip
   on the milestone view.** Ruling 5's reasoning generalises: each of those is a derivation that
   already exists exactly once elsewhere. All three are asserted absent by test, and each view links
   to the screen that owns the derivation.
