## Findings

1. **All eight detail views need the same two primitives and no Wave C unit owns `src/components/`.**
   `ProseValue` (the four-state `Prose` renderer) and `EngagementLink` are duplicated **three times**
   in this unit, byte-identical, each carrying a header saying so. That is a real cost — one wording
   in three places that must not drift — and it was paid deliberately: creating
   `src/components/detail-prose.tsx` is outside my ownership, and f2 and f3 need the identical thing,
   so three parallel worktrees each creating that file is a three-way merge conflict on a file none
   of us may edit. **Recommendation: a follow-up unit factors them out after Wave C merges, and f2/f3
   are pointed at my wording in the meantime** rather than each choosing their own words for
   `unreadable`. Eight views showing the same failure three different ways is a product defect, not a
   style question. Queued as questions 1 and 2.

2. **`DetailField`'s `absent` prop is inert on every prose row.** `DetailField` renders its own
   `Absent` only when `children` is `undefined`/`null`/`""`, and `ProseValue` always returns an
   element — so on prose rows the string is passed to both and only `ProseValue`'s is ever shown.
   Harmless, but it means the same sentence is written twice per prose field. It is written twice
   rather than once because `absent` is a required prop of a component I may not edit. Worth
   collapsing when Finding 1 is addressed.

3. **`WorkItemDetail.evidenceScope` and `EvidenceScopeChip` disagree on spelling, and getting it
   wrong is silent.** The loader returns FR-43's hyphenated wire form (`observed-elsewhere`); the
   chip takes Postgres' underscored form (`observed_elsewhere`). `EVIDENCE_SCOPE.parse` returns
   `null` on a miss and the chip renders `null` as **"no scope recorded"** — so a wrong mapping
   claims nothing was recorded about a row that recorded something, which is this product's worst
   output class. I used an exhaustive `Record<EvidenceScope, StoredEvidenceScope>` instead of
   `.parse`, so a fifth scope breaks the build rather than rendering a false absence. **f2 and f3
   will hit the same split** on any view that renders an evidence scope or an unautomated reason.
   Mutation M4 confirms a wrong entry goes red.

4. **`defect.wont_fix_reason` is baseline-sourced, not §7a.** As i1 stated (B13), §7a is silent on
   this column and the security baseline is what encrypts it. It is rendered here on the same
   four-state footing as the §7a fields, because a `wont_fix` decision whose stated reason could not
   be read back is not the same as one that never had a reason — and FR-67 makes that decision
   first-class. Recorded so the control's provenance is not lost.

5. **`src/app/work-items/unassigned/` survives its new `[id]` sibling** — `pnpm build` lists both
   `/work-items/[id]` and `/work-items/unassigned` and raised no route conflict. That is consistent
   with u1's measurement (which included a positive control) but it is **weaker evidence than u1's**:
   a build that accepts both routes is not the same as observing the static one win at request time.
   I did not re-measure, because doing so needs a running server and `pnpm e2e` was out of scope for
   this unit. Treat u1's measurement as the load-bearing one.

## Best-guess decisions

1. **`loadForOperator` wraps the loader call, rather than a bare `try` as in
   `registry/[slug]/page.tsx`.** The registry precedent predates that wrapper and hand-rolls the
   same three outcomes. `loadForOperator` is the module that already refuses to collapse "could not
   read" into "there is nothing here", and it distinguishes the four refusal reasons the operator
   has to act on differently. `notFound()` is still called **outside** it, because it signals by
   throwing and the wrapper's `try` would otherwise swallow a 404 into the failure notice. Asserted
   by M1, M7 and M11.
2. **The failure path renders bare `Screen` + `OperatorLoadNotice`, not `EntityDetail`.** A page that
   could not read the row must not emit `data-verify-unit="entity-detail"` — that element is a claim
   that a row was read. So the shell appears on the success path only, which is also what keeps
   "exactly one per page" true.
3. **`withProse` is left at its default `true` on all three loaders.** FR-81 asks for decrypted
   prose by name, so no view here ever renders `not-requested` in production. The branch exists and
   is tested because i1's type has four states and a view that renders one of them as blank is
   making a false claim — not because this unit will produce it.
4. **A work item with no `unit` is titled by `fallbackLabel` and its identifier slot is drawn
   absent.** `hand` and `external` work carry no unit. Both facts are shown — a display name so the
   heading is not blank, and an explicit absence so nobody reads the display name as a reference.
   No second fallback was invented; `fallbackLabel` is i1's.
5. **A blocker's missing `owner` is NOT defaulted to `erik`.** FR-52's default is applied at ingest;
   a row that reached the database with no owner is a gap in the record, and drawing it as one of
   Erik's would move somebody else's backlog onto his screen. Asserted by M12.
6. **Both defect severity spellings are rendered side by side.** `severity` is the enum the parser
   produced and `rawSeverity` is the grading word the artifact wrote. Where they disagree, the
   disagreement is the data — this repo's rule, applied to a display. Asserted by M8.
7. **A dangling reference stays in its list rather than being filtered out.** A `blocker-blocks`
   count of 2 with one dangling member is the honest answer; filtering would under-report what a
   blocker is holding. Asserted by M13.
8. **`test_case` gets no `<EntityRef>` and no anchor at all.** It is not one of FR-81's eight kinds,
   `entityHref` can build no destination, and a link this product cannot build is the broken link
   FR-83 forbids. Rendered as named facts instead. Asserted by M9.
9. **The empty-tests sentence differs by whether the defect has a `D-nn`.** "No test names D-7" and
   "there is no D-nn for a test to name" are different facts about the same empty list.
10. **Back links point at the answer screen each entity appears on** — `/work-items`, `/broken`,
    `/blocked` — because no `/defects` or `/blockers` index exists and inventing two listing screens
    is outside this unit's scope. Queued as question 3.
