
```tsx

<EntityRef kind={EntityKind} label={string} id={string | null} title?={string} className?={string} />
<EntityRefList refs={readonly EntityRefItem[]} empty={string} />
type EntityRefItem = { kind: EntityKind; label: string; id: string | null; title?: string };
```

```tsx
// src/components/entity-detail.tsx
<EntityDetail kind title question requirements? identifier? actions?>{children}</EntityDetail>
<DetailSection heading requirements? verifyUnit?>{children}</DetailSection>
<DetailFields>{children}</DetailFields>
<DetailField label absent mono?>{value}</DetailField>
```

Three notes for the adopting units:

1. **`id` is the database uuid, never the human ref.** `entityHref("requirement", "FR-42")` builds
   `/requirements/FR-42`, which is a broken link — exactly what FR-83 exists to prevent. Resolve the
   ref to a row id first; if it does not resolve, pass `id={null}` and the dangling treatment is
   automatic.
2. **`DetailField`'s `absent` is required**, deliberately. A value that was never recorded renders
   as `Absent` with a stated reason, never blank and never `0`.
3. **`DetailSection`'s `verifyUnit` is a passthrough** because FR-82 asserts on four sections by
   name (`requirement-work-items`, `requirement-tests`, `requirement-defects`,
   `requirement-releases`). Those names belong to the requirement view, not to the shell.

`/work-items/unassigned`. The probe route was deleted, the server stopped, and the tree re-verified

## Best-guess decisions

1. **`entityHref` trims the id before encoding.** `entityHref("defect", "  abc  ")` →
   `/defects/abc`, not `/defects/%20%20abc%20%20`. A whitespace-padded uuid is the same uuid, and
   the padded path would 404. A whitespace-only id remains `null` (the gate requires it).
2. **`entityHref` takes `kind: string`, not `EntityKind`.** The gate calls it with
   `"not_an_entity"`, so the signature must accept an unrecognised string and refuse it at runtime.
   `isEntityKind` is the narrowing.
3. **`EntityRef` computes `known` from `entityHref(kind, id)`, not from `id !== null` alone.** So a
   caller who passes a whitespace-only id gets the dangling treatment rather than a link to
   nowhere. There is exactly one predicate and it lives in `entity-routes.ts`.
4. **Added `data-verify-unit="entity-link"` to the anchor.** Additive; no gate depends on it. It
   makes the anchor queryable directly instead of only through `closest()`. Say the word and it goes.
5. **`ENTITY_BASE_PATH` and `ENTITY_LABEL` are exported.** The brief mandated `ENTITY_LABEL`; I
   exported the path map too, so a detail route can assert its own location against the table rather
   than against a path someone retyped.
6. **`DetailSection` derives its `aria-labelledby` id from the heading text.** Two sections with the
   same heading on one page would collide; that seemed less likely than eight views each inventing
   an id scheme. If it bites, the fix is an optional `id` prop.
