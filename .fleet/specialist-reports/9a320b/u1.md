## Best-guess decisions

1. **The run id links to `/runs/<run-id>`, a route `u2` owns and I cannot see.** A listing whose
   primary key is not navigable would be half a feature, and the manifest sequences both units into
   one invocation. If `u2` fails, this link 404s — flagged as a cross-unit coupling for the
   orchestrator to confirm at merge, not queued as a question.
2. **No colour on a non-zero `failed` test count.** Spec 5a reserves the semantic scale for its
   named states, and these are counts the artifact *claimed* rather than results this product
   observed. Painting a claimed failure with the weight of an observed one overstates what the row
   knows. Reversible in one line if Erik wants it louder.
3. **Nine columns, no truncation.** FR-92 names eight facts and FR-94 adds a ninth. I put them all
   in one horizontally scrollable table rather than hiding any behind a disclosure, matching the
   instrument-panel direction. Unverified at 375px — see the honesty section above.
4. **The two notes are conditional, not permanent copy.** Stated here because "the note disappeared"
   is a behaviour a reviewer could otherwise read as a bug.
5. **D1 tension, resolved toward the brief.** The manifest's D1 contemplates `gates` supplying a
   second verdict source; `i1` implemented a firm refusal to synthesise one, and my dispatch brief
   repeats that refusal. I followed `i1`'s model and added a test asserting a run with populated
   `gates` still exposes exactly one verdict source. If Erik intended `gates` to be mined for a
   verdict-bearing key, that is a change to `runs-display.ts`, which I must not edit — it would need
   a new unit.
