## The contract `u1` and `u2` build against

`@/lib/server/*`.

| Export | Shape | For |

| `readRunDetail(runId)` | `Promise<RunDetailResult>` | `/runs/[run-id]` (FR-93, FR-94, FR-95) |

`<EntityRef>`'s props by definition. `fleet_run` is deliberately **not** added to `ENTITY_KINDS` —
that set is pinned at exactly 8 by `tests/entity-routes.test.ts:25` and `tests/m27-gate.test.ts:109`,
and `/runs/[run-id]` is keyed by the human run id rather than a uuid, so it was never an

## Best-guess decisions

1. **FR-94's per-run population differs from FR-58's global census, and I did not reconcile them.**
   The badge reads 0 while run `b0952e` reads 1 (its `verdict` is literally `unparsed`, which the
   census's three-table population cannot hold). `answers/unparsed.ts` explicitly owns the global
   definition, so I narrowed one of its predicates to a run and returned the components broken out
   rather than a bare number — and queued the reconciliation. Rationale: the census's own author
   justified adding `test_result` with "a classifier default that is never counted is a silent one",
   and `fleet_run.verdict` is currently counted nowhere.
2. **`opened: null`, typed as the literal `null`, not `DetailRef[] | null`.** A UI handed `[]`
   renders "this run opened no defects". The literal type makes that mistake impossible to make.
3. **No page limit on `/runs`.** FR-92 says "every ingested fleet run", so a cap would violate the
   requirement rather than guard it; `fetchAllRows` is exhaustive-or-loud.
4. **`RunDetailResult.ambiguous` exists although it cannot fire today** (1 run, 2 engagements).
   `unique (engagement_id, run_id)` makes the route key non-unique in principle, and taking the first
   match would render one engagement's run under an id that also belongs to another's.
5. **`reconcileVerdicts` is exported and tested with fabricated two-source input.** Today's schema
   yields one source, so FR-95's "both are shown" branch would otherwise be code that never runs. I
   did **not** synthesise a second source from `gates` to make it light up on real data (D1).
6. **Ordering caveats stated rather than hidden.** A run with no `started_at` sorts last, not as the
   epoch, and the tail of the list is not a chronology — the same caveat `questions-load.ts` carries.
