Four design calls worth naming:

**FR-66's join runs through the fixing work item and nothing else.** The certifier is compared
against the executor of *that* work item, never against the set of executors in the engagement.
The vault note `A certifier check must join through the requirement to the work item that
implemented it` predicted the widened form in prose; run b0952e measured it against i2's coverage
suite and all seven assertions still passed. So the fixture here carries **two parties whose roles
cross** — `api-integrator` builds `w1` and certifies `w2`'s fix, `qa-reviewer` does the reverse —
and I confirmed it catches the widening before trusting it (mutation 1 below).

**A defect with no fixing work item cannot be verified.** There is no party for the certifier to
be independent of, so the condition is vacuous rather than satisfied. Reported as
`blockedBy: "no-fixing-executor"` rather than waved through — a vacuous pass here is exactly the
wrong `done` this product exists to prevent.

**FR-69's two kinds are computed independently, not one from the other.** A test can go red with
no requirement losing coverage (a second test still covers it), and a requirement can lose
coverage with no test going red at all (the latest passing run was self-certified). Both cases are
asserted.

**FR-70 needed no new rule, only an observation.** `committedReport` computes the gate against
*current* coverage — the latest result per test — so a covering test going red removes the FR-47
coverage FR-50 requires and the milestone leaves `billable` on its own. Mutation 5 is the proof
that this actually happens rather than being merely argued.

## Security posture applied

My functions touch no database, so I inherit no direct encryption duty. What my **signatures**
decide is whether a caller must decrypt, and that is stated per table:

| Table / entity | Class | Source | What my code does with it |
|---|---|---|---|
| `defect` | sensitive | spec §7a as amended by CR-001 | `Defect.description` and `Defect.wontFixReason` are typed `string \| null` and documented as **plaintext — ciphertext at rest**. A caller passing them is decrypting deliberately. |
| `defect.title` | sensitive, **stated clear exception** | CR-001 §4 | Read and returned in the clear. This is the display key on Broken; the exception is CR-001's, not mine. |
| `requirement` | sensitive (`text` encrypted; `ref` clear) | spec §7a | Every join in this unit is by `FR-nn` or `D-nn`. **Nothing here matches, sorts or joins on `requirement.text`** — ciphertext cannot be indexed or compared. |
| `release`, `release_requirement`, `test_result`, `test_case` | internal | spec §7a | Provider default; no special handling needed and none added. |
| `contract_milestone` | sensitive (`amount` encrypted) | spec §7a | `Milestone.amount` is carried through untouched and **never read** by any rule in this unit. No decrypt is required to compute billable, shipped or contested. |

**Functions requiring decrypted input:** none. Every rule in this unit runs on `ref`, `status`,
`severity`, `certifiedBy`, `executor` and dates — all clear columns. `description` and
`wontFixReason` are carried but never inspected, and `parseQaFindings` produces plaintext from a
QA report that was already plaintext on disk. **A caller can compute the entire Broken and
Committed answers without decrypting a single sensitive column.** That is a property worth keeping
when i6 wires the persistence layer.

Controls from §7a: 5 (the table above) · from baseline: 0 · **NOT VERIFIED: 0 encryption controls,
because this unit implements none** — see Verification for what that does and does not mean.
Unclassified tables I refused to guess at: none — every entity I touch has a §7a row.

No secret is read, written, logged or referenced anywhere in this unit. There is no
`process.env` access in the package, by the plan's Global Constraints.

## Best-guess decisions

- **Append order is history order.** `latestResults` does not re-sort by `runAt`. `test_result.run_at`
  is nullable, an undated result cannot be placed in a sequence, and silently choosing an order for
  it decides whether a regression is reported or hidden. The contract is documented on the function;
  the database read that feeds it orders by `run_at`.
- **`evidence_scope` does not gate FR-66.** FR-47 has an explicit `not-verified` rule (FR-49) and
  FR-66 states two conditions only — a passing test naming `D-nn`, and an independent certifier. I
  implemented exactly those two rather than importing FR-49's stricter rule by analogy.
- **A `wont_fix` defect is never re-opened by a later passing test.** FR-67 makes it a decision,
  and a decision is not something a test result overturns.
- **An `unparsed`-severity defect does not contest** (it is not known to be critical) **but is
  reported in `unclassifiedDefects`** on the milestone verdict, so a milestone is never shown clean
  while a finding nobody has graded names one of its acceptance requirements. FR-79 says "never
  presented as clean"; this is how that holds for the ungraded case.
- **The finding *title* falls back to the line text when there is no bold span.** The title is free
  text, not a classified field — transcribing it is not a guess. The classified field is `severity`,
  and that carries the unparsed discipline alone.
- **`parseQaFindings` extracts no fixing work item.** The QA report template carries no such field;
  inventing a `fixed by <unit>` pattern for a shape the artifact does not use is precisely the move
  the unparsed rule forbids. I wrote that pattern into the fixture first, noticed it was my own
  invention, and removed it.
