## What I built

### The finding: partial unique indexes make every upsert fail on the second post

Measured on the live project **before** writing the writer, against an existing row:

```
insert ... on conflict (engagement_id, fleet_run_id, unit) do update ...
  -> ERROR 42P10: there is no unique or exclusion constraint matching the ON CONFLICT specification

insert ... on conflict (engagement_id, fleet_run_id, unit)
    where fleet_run_id is not null and unit is not null do update ...
  -> INFERRED
```

Postgres infers a partial unique index only when the statement restates the predicate. PostgREST's
`on_conflict` is a query parameter carrying column names, with no way to express a `WHERE` — so
`supabase-js` emits the first form and fails every time. i1's index comment names the correct SQL
(predicate included); the problem is that no PostgREST client can emit it.

Two indexes were affected: i1's `work_item_engagement_run_unit_key`, and
`open_question_source_key_idx`, which this unit had itself created partial an hour earlier.
Migration `20260819170622` replaces both with plain unique indexes. Nothing is lost:
`NULLS DISTINCT` (the default) already exempts hand and external work items, which carry neither a
run nor a unit — the exact rows the partial predicate excluded.

**Why this was worth a migration rather than a workaround:** it fails in the most expensive
direction available. The schema looks right, the TypeScript compiles, the first ingest of any run
succeeds, and the break appears only when a run is re-posted.

### `open_question.source_key` — FR-22's missing key

i1 left this open in the table comment: idempotency here "needs a plaintext digest column or a
delete-and-reinsert-per-run strategy". Re-measured why no encrypted column can serve:
`select encrypt_field('same') = encrypt_field('same')` returns **false** — pgp_sym output is
non-deterministic.

Delete-and-reinsert was rejected because it destroys operator-entered answers. The key is
`<questions filename>#<record ordinal in that file>`, clear text carrying a filename and an
integer and no prose, so the table's `sensitive` class is unchanged.

Answers are protected structurally: questions are upserted in **two batches**, and the batch for
records the artifact states no answer for **omits the answer columns entirely**, so
`ON CONFLICT DO UPDATE` cannot overwrite what Erik typed.

### FR-20 and FR-21 had no parser; both shapes came from documents, not from a sample

Neither requirement had an implementation and `plan.md`'s file list has neither. Rather than infer
a format from one artifact:

- FR-20's status vocabulary is `project-lead.md`'s Build-log writeback step 2 (`Complete`,
  `In Progress`, `Blocked`, `Deferred`) plus the two words the live `prod.md` carries (`Done`,
  `Not Started`). Anything else is `unparsed`.
- FR-21's shapes are `project-lead.md` Phase 5 step 3 (the checkpoint's `key: value` block) and
  `qa-reviewer.md`'s report template (`**Status:**`, the severity tally, `## Verification
  performed`).

**Only the outcome word is stored, never the reason excerpt.** `- Build (pnpm): FAIL <excerpt>`
contributes `"build":"FAIL"` and the excerpt is discarded, because an excerpt is specialist prose
and `fleet_run` is `internal` — storing one would push a table past its own §7a classification.

### FR-20's milestone tracker is parsed and deliberately NOT persisted

The 21-entity schema has no build-milestone entity and §7a classifies none. An entity with no §7a
row is a blocker, not a default, so no 22nd table was created. The tracker is returned in the
ingest response and reported under `notPersisted` with the reason. **Queued as a question.**

### The `unparsed` discipline, downstream

Nothing in the persistence path inspects a status it was handed and improves it. `planRun` carries
`unparsed` through to the column, and the count travels with it in `apiOk(…, { unparsed })`.
Separately, every value the enum seam cannot map returns `null` and is **counted** in
`summary.unmappable` rather than defaulted — a non-integer `phase`, an unrecognised `confidence`,
a duplicate unit id within one run.

### FR-23, made structural rather than promised

The ingest path imports no `fs`, no `path`, no `child_process`, and takes artifact *contents*, not
paths — `payload.ts` rejects any filename containing a separator. There is no handle to write
through. The only `node:fs` import in the whole ingest package is inside a test.

### FR-16, enforced at the boundary

`parseWorkUnits` scopes a unit by the run in the manifest *filename*, while the route writes
against one `fleet_run`. A payload mixing runs would collide two distinct `i1` records, so a
manifest whose derived run differs from the declared `run` is refused with a 400.

## Best-guess decisions

1. **FR-20's milestone tracker is parsed but not persisted**, because no §7a-classified entity
   exists for it. Queued.
2. **Two new parsers went into `src/lib/ingest/`** rather than my own directory, because
   CLAUDE.md's "parsers are pure functions over text" convention lives there and both are pure.
   New filenames only, so no merge collision with i6/i8.
3. **`blocker.owner` default changed to `"erik"` in `blocked.ts`** — I made this change; it had not
   been made. The manifest's Blocked table has no Owner column, so this default governs every
   blocker parsed from a manifest. `prodMd.ts` reads a stated owner where the artifact has one.
4. **prod.md's blockers win over the manifest's on a `ref` collision**, because prod.md carries an
   explicit Owner column and a resolution state and the manifest carries neither.
5. **`Done` and `Complete` map to one tracker status.** Both appear verbatim in these artifacts and
   mean one state; `raw_status` is preserved either way.
6. **Payload bounds (8 MB / 200 files / 2 MB each) are mine.** §7a gives a request rate, not a body
   size. Roughly two orders of magnitude above the real corpus.
7. **One RPC round trip per encrypted field**, rather than a bulk stored procedure. §7a's traffic
   shape is a few ingests a day; moving record-shaping into SQL would make it untestable to save a
   fraction of a second.
8. **A partial index was replaced rather than worked around.** The alternative — restating the
   predicate — is impossible over PostgREST.
9. **`fleet_run.gates` stores only outcome words**, never the reason excerpt, to keep an `internal`
   table free of specialist prose.
10. **`work_item` dependency/requirement children are reconciled (delete-then-write)**, so a
    corrected manifest removes a stale edge instead of accumulating one.

2. **`git checkout --` cannot revert an untracked file**, so a mutation harness that reverts with
   git silently accumulates mutations across a whole run and makes every verdict unattributable.
   *Evidence:* observed in this unit — `error: pathspec '…' did not match any file(s) known to git`
   repeated for 12 mutations, tree left mutated, restored by inverse patch and re-run with an
   in-memory snapshot. Recorded in `CLAUDE.md`.
